# ステップ5-A：永久継承込みのボスバランス調整準備

2026-11-17 JST / `feature/boss-balance-final` / 開始HEAD `c69fd98`。

## 結論と調整の前提

**1・8階を強化検討の優先候補、6階を継承込みの強化再評価候補とする。5階は継承・装備で評価が逆転するため弱体化を急がない。7階は魔法火力を下げる案を検討する。12階は魔法職Cの構成を先に修正・確認し、全体調整を保留する。** いずれも能力値の変更は適用していない。

推奨条件でB約10%（暫定5〜15%）、C約50%（40〜60%）を正式目標とする。今回は各条件5戦のスクリーニングで、適正難易度や最適戦術を確定する測定ではない。現時点で「全7職業のB/Cが目標に適合した」と判定できる階はない。

魔法職のC候補は7・12階でBを下回った。これは弱いBを作って差を演出する理由にも、直ちにボスを弱体化する理由にもならない。**今回測ったC1と、次に確認する未測定C2を明確に分ける。** Cを攻撃重視と名付けただけでは、実効火力・勝率の優位を保証しない。

## 調査と変更範囲

現在の`BattleEngine`、`initialize_presets`、スキル認可、`SkillPreset`、回帰時抽選、職業変更証、Ver.2測定器と旧結果を照合した。

- `profile_tactic()`でprofileに明示したB/Cの順序・使用回数を受け取り、実アプリと同じ`available_skills()`で許可する。旧profileは旧TACTICSへフォールバックし、旧戦術定義を変更しない。manifestには実際の枠を記録する。
- `balance_stage5.py`で評価専用の戦術・装備・継承履歴を構築する。通常DBにはアクセスせず、育成条件の構築中はSQLを禁止する。
- ランナーに`--max-seconds`を追加。DB準備からの経過時間を戦闘間で確認し、上限でJSONL/manifestを残して終了する。単一戦闘・DB破棄のハードリアルタイム制限ではない。今回の実行は上限未到達。

ボスHP/MP/能力/技能、成長式、スキル倍率/消費MP/発動率、ダメージ式、ゲージ式、強化式に変更なし。通常DB/本番DBへのmigration・更新・削除なし。Gitのcommit/push/mergeなし。開発DBへのmigration・ブラウザー確認完了は今回ユーザーからの報告として扱い、通常DBの読出しで再検証していない。

## 永久継承の採用条件

新仕様では回帰するたびに未習得があれば必ず取得する。回帰数10なのに永久習得0という条件は、通常の新規育成経路では到達しない。今回の`none`は旧仕様/未移行育成との対照であり、回帰済みの推奨条件にはしない。

`trained`は先に職歴を決め、結果を見て良い個体だけを採用しない。

|現在職業|最初の5回の回帰前職業|次の5回|10回時点の永久習得|
|---|---|---|---|
|拳闘士・重戦士・狩人・放浪人・暗殺者|拳闘士|プリースト|各5種、計10種|
|ウィザード|プリースト|放浪人|同上|
|プリースト|ウィザード|放浪人|同上|

同一職業を5回経験すると、重複禁止の抽選によってその5種は**確率1で揃う**。10種を特定の順番で引く確率を要求しない。2回帰では職歴の先頭2回だけを再生し、seed50361117で引いた2種類をそのまま記録する。5回帰では最初の1職業を揃える。残りの回帰は既に5種習得済みの職業を繰り返す、追加なしの合法な経路として圧縮記録する。各回帰後は放浪人へ戻り、次の回帰前職業と現在の育成職業へ職業変更証で転職する前提。

取得数≦回帰数、各回の回帰前職業、未取得からの抽選、履歴と取得一覧、追加なしが許される条件をコードで検証した。現在職業の固有技能と取得済みが重なっても永久所有数には含むが、戦術候補は重複させない。

名称・由来・MP・種別は[スキルカタログ](balance_stage5a/analysis/skill_catalog.json)、取得順・職業・残回帰は各profileの`inheritance_history`/`inheritance_remaining`を参照。未完成3種も取得リストに存在し得るが、戦術には採用しない。新システム開始前に回帰済みだった既存キャラクターは取得済み数が少ない場合があり、この10種を保有済みとみなしていない。

## 7職業の戦術B/C

[戦術の全表](balance_stage5a/analysis/TABLES.md)に、継承なし/あり各7職業の名称・順番・使用回数を掲載した。元のB/Cを上書きせず、今回のprofileに明記している。最大5枠、使用予算は有限、現在のMP/発動率/成功時消費/枠進行に従う。

- 拳闘士：Bは闘魂→真拳→ダブルパンチを主軸に、継承ありはシールドも使用。Cは闘魂/回復の行動を攻撃へ配分。
- 重戦士：継承なしBもフレア/一撃を攻撃主軸とし、旧Bの防御2枠による長期化を避ける。継承ありは真拳/ダブルパンチと一撃を比較する。
- 狩人：継承なしは毒と必中攻撃を主軸にBは命中補助を含む。継承ありはSTR/LUKを活かす拳闘士技も利用し、Cは毒を追加。
- ウィザード/プリースト：継承ありBは自由パッシブ＋アンチジェイル/ジャッジメント＋回復。測定C1は回復を外しアンチ/ステラ/メギドへ配分した。
- 放浪人：自由をB/Cの両方に置く。継承なしは歩行者による速度低下を避け、核心を主軸とする。継承ありは真拳/ダブルパンチを使用。
- 暗殺者：継承なしBはステルス/毒/反射、Cは奇襲/毒で自傷リスクも維持。継承ありでは拳闘士技を利用し、Cに毒を残す。

Bを目標10%へ合わせるため意図的に弱くしない。継承により複数の職業が同じ高倍率技へ集まる傾向も観測対象であり、現職固有技が必ず最適という前提を置かない。

### 魔法職C2の修正案（未測定）

「自由×1 → アンチジェイル×12 → ジャッジメント×8」を提案する。Bの強い攻撃を維持し、回復の行動を攻撃へ回す。無制限使用やMP追加はしない。全キャラクター条件・継承はBと同じ。[C2提案JSON](balance_stage5a/analysis/C2_PROPOSAL_UNMEASURED.json)は`proposal_unmeasured`として保存した。

12階の継承ありウィザードはB4/5・C1 0/5、平均残MP11,679/11,710で枯渇していない。Bの回復は平均7,212、プリーストは8,246。回復を除いた生存時間短縮と、ステラの各ヒット防御減算がC1の弱さの候補。ボスINT5,600なら毎ヒット1,680を減算し、アンチの高倍率2連撃とステラ4〜5連撃の効率は同じではない。

C2でも回復を外すことが不利な相手には勝率が上がる保証はない。B/Cの実効差が乏しいまま、ボス能力だけで全職業の10%/50%を同時達成できるとも限らない。まず構成を検証する。

- `manage.py check`、構文検査、差分空白検査、新旧seed分離、旧重複digest、B/C全profile同一、実行した枠とmanifestの一致、継承履歴、全35スキルのDBカタログ一致を検証する。

## 成果物・再現・安全性

新データは`docs/変更詳細/balance_stage5a/screen_confirmed/`。全条件manifest、seed、JSONL/CSV、summary、selection、測定時のソースSHA256索引を保存。サンドボックスDB接続失敗時の`screen/`も保持し、再実行先を分けた。旧成果物のSHA256索引は`analysis/old_sha256.json`に保存した。

# DB作成なしで規模確認
